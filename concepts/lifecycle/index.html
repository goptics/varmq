JOB 03Core concepts

Worker lifecycle

A worker is always in one of seven states. Status() returns the current one as a string, and five Is* methods answer yes or no for some of them.

The diagram below is a worker you can drive. Click a state to read about it. Press a method to call it. The worker has three jobs waiting and runs one at a time, taking every waiting job into one batch. Pause and Stop never interrupt a running job, so press Finish to end it.

The seven states

Section titled “The seven states”
State What it means Is* check
Initiated Created with WithAutoRun(false) and not started yet. none
Idle Started, with no job running. IsIdle, IsActive
Running At least one job is running. IsRunning, IsActive
Pausing Pause was called while jobs were running. They finish, and the worker takes no new ones. none
Paused No job is running and none will start until Resume. IsPaused
Stopping Stop was called. Running jobs finish, then the worker’s goroutines are removed. none
Stopped The event loop has ended and the goroutines are gone. Jobs still in the queue stay there. IsStopped

Idle and Running swap on their own as jobs start and finish, so Running is a moment, not a mode you set. IsActive is true for either of them, which makes it the check for “started and not paused or stopped”.

Once job 1 is done it is Paused, and jobs 2 and 3 wait until Resume. When they are done the worker is Idle again.


A status is a snapshot. Between reading it and acting on it the worker may have moved on. To know where a worker has landed after Pause or Stop, use the waiting helpers below.

The errors are values in the package, listed under Variables. Two details:


    

  • Pause, Resume and Stop return at once. Restart does not: it waits for running jobs to finish before it starts the worker again. If another goroutine restarts the worker first, it returns ErrRunningWorker.
    • 

  • A stopped worker cannot be resumed. Resume returns ErrWorkerStopped. Use Restart, or Start, which also accepts a stopped worker.
    •

What happens to jobs
Section titled “What happens to jobs”


Pause and stop never interrupt a running job. Each running job finishes first.


Jobs that have not started stay queued and are not lost. A worker may have taken several jobs from the queue at once (see how it works). On pause or stop it finishes the job it is running and parks the rest of the batch. Parked jobs are still Queued, and the worker’s NumPending counts them, but the queue’s Len() does not. They run first, in their original order, after Resume or Restart. Purge closes them.


A stop also cancels the worker’s Context(). A restart gives the worker a fresh one.


Waiting for a state
Section titled “Waiting for a state”


Pause, Resume and Stop only start the change. These block until it is done:


    

  • PauseAndWait is Pause followed by WaitUntilPaused.
    • 

  • StopAndWait is Stop followed by WaitUntilStopped.
    • 

  • WaitUntilPaused and WaitUntilStopped wait for one state, and never return if the worker does not reach it.
    • 

  • WaitUntilIdle waits for Idle with no pending jobs, so on a paused or stopped worker it keeps waiting until Resume, Restart or Start brings it back to Idle and it drains.
    • 



WaitAndPause and WaitAndStop go the other way: they call Wait first, then pause or stop. Waiting compares all of them.


Settings
Section titled “Settings”


WithAutoRun
Section titled “WithAutoRun”


WithAutoRun decides whether the worker starts when you create it. The default is true: NewWorker returns a worker that is already Idle, and Start on it returns ErrRunningWorker.


Pass WithAutoRun(false) to get an Initiated worker instead. You can bind queues and add jobs to it right away. The jobs wait until you call Start. Use it when you want to finish setting things up before any job runs.


WithStoppedRetention
Section titled “WithStoppedRetention”


This setting matters only for a worker with a name (WithName or a string argument to NewWorker). Start adds a named worker to WorkerRegistry, the map that the REST Handler reads. A worker without a name is never registered.


When a registered worker reaches Stopped, it stays in the registry for a while, so it still shows up as Stopped. WithStoppedRetention sets how long. When the time is up and the worker is still stopped, it is removed from the registry.


    

  • The default is one minute. DefaultStoppedRetention changes the default for workers created after the call.
    • 

  • 0 turns the cleanup off: a stopped worker stays in the registry for good.
    • 

  • Starting the worker again cancels the timer, and re-registers the worker if it had already been removed.
    •
