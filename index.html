What you get
Section titled “What you get”


Typed jobs and results
A job carries your type. A worker can also return an error, or a result and an error, that you
read from the job. See worker types.
Priority queues
Add a job with a priority and the lowest number runs first. See queues.
Several queues, one pool
Bind many queues to one worker and choose how it picks between them. See
strategies.
Topics
Publish once and every subscribed worker gets its own job. See topics.
Persistent and distributed queues
Keep jobs across restarts, or share a queue between processes, with a storage adapter. See
persistence.
Control at runtime
Pause, resume, restart or resize a running worker, from code or over HTTP. See
lifecycle and the REST API.

Performance
Section titled “Performance”


Measured on an i7-13700 (24 threads) on 2026-10-25. Charts, raw results and the harness are at benchmarks.goptics.org.


4.89M tasks/s
Average over 15M tasks per run, 50K workers, 1 to 1M producers. The next fastest pool, a
hand-rolled buffered channel pool, does 2.73M, and ants 2.22M. It uses more memory: 115 MB per 1M
tasks against 15 MB for ants, because Add never blocks.
59,898 jobs/s on Redis
With redisq, one instance with 100 workers, moving 100K no-op jobs from 100 producers. The median
time from enqueue to handler is 0.058 ms.
14,725 jobs/s on SQLite
With sqliteq, draining 20K jobs on WAL. goqite does 2,933 and River 3,230 on the same run.


The comparison lists features side by side with other Go worker pools.
