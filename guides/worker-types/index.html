JOB 01Worker pool guides

Worker types

varmq has three worker constructors. In each, your worker function receives a Job[T], where T is the type of the data you pass to Add. They differ in what the function returns. That decides what Add hands back, and how you find out what happened to a job.

Constructor Your function Add returns Read the outcome with
NewWorker func(j Job[T]) EnqueuedJob nothing to read
NewErrWorker func(j Job[T]) error EnqueuedErrJob Err() error
NewResultWorker func(j Job[T]) (R, error) EnqueuedResultJob[R] Result() (R, error)

Pick a constructor and a job below. The same function runs under all three, so you see what changes: the type Add hands back, and where a failure shows up.

R is the type of the result. Add returns the handle together with a bool, false when the queue did not take the job. Jobs covers both.

A plain worker

Section titled “A plain worker”

NewWorker is for work that has nothing to report back. The handle lets you Wait for the job, read its status or close it while it waits, but it carries no outcome.

Tab inserts a tab. Esc leaves the editor. Ctrl+Enter runs.



The worker’s function prints worker got hello. Wait returns once the job is done, and there is nothing else to read from the handle.


If the function panics, the worker recovers, counts the job as failed, and reports the panic on the worker’s Errs() channel and to the handler you set with WithErrHandler. The handle does not get it. Errors covers both.


An error worker
Section titled “An error worker”


NewErrWorker takes a function that returns an error. Err() blocks until the job is closed, then returns what the function returned: nil when it succeeded. A panic comes back through Err() as an error. The worker reports the same error on its own Errs() channel and to its error handler too, so one failure shows up in both places.


A job that was closed before it ran also releases Err, with nil. So nil means the function reported no error, not that it ran. See closing a queued job.


Tab inserts a tab. Esc leaves the editor. Ctrl+Enter runs.


Err returned what the function returned for each job: <nil> for 2 and 3 is odd for 3. The program reads each outcome right after Add to stay short. In a real program you usually add many jobs first and read the outcomes later.


A result worker
Section titled “A result worker”


NewResultWorker takes a function that returns (R, error). Result() blocks until the job is closed, then returns both.


When the function returns a non-nil error, Result returns that error and the zero value of R, whatever value the function returned beside it. A panic does the same: the zero value, and the panic as the error. As with an error worker, the error also reaches Errs() and the error handler.


Tab inserts a tab. Esc leaves the editor. Ctrl+Enter runs.


"42" gives the result 42 and no error. "forty-two" gives the zero value of int and the error from strconv.Atoi.


What a handle has
Section titled “What a handle has”


Every handle has ID(), Status(), IsClosed(), Wait() and Close(). The error and result handles add Err() or Result(), and a Drain() method.


Drain does nothing on a single job. It exists for the group handles that AddAll returns (adding many jobs), so Err and Result give the same answer whether or not you call it.


Which queues each worker can bind
Section titled “Which queues each worker can bind”

An error or result worker binds in-memory queues only. For a persistent queue, a distributed queue or a topic, use NewWorker.


The handles in this guide are what an in-memory queue’s Add returns. On a persistent or distributed queue, Add returns only a bool, false when the storage refused the job. There is no job handle, so there is nothing to Wait on or to read an outcome from.
