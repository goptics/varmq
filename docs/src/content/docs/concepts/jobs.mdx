A job is one unit of work: your data, an optional ID, and a status that changes as the worker runs it. You never build one yourself. [`Add`](https://pkg.go.dev/github.com/goptics/varmq#Queue.Add) creates it, puts it in the queue and gives you a handle.

## Two views of a job

The worker function and the code that called `Add` see different things.

**The worker function gets a [`Job[T]`](https://pkg.go.dev/github.com/goptics/varmq#Job).** It has three methods. [`Data()`](https://pkg.go.dev/github.com/goptics/varmq#Job.Data) returns what you passed to `Add`, and [`ID()`](https://pkg.go.dev/github.com/goptics/varmq#Identifiable.ID) returns the job's ID. [`Context()`](https://pkg.go.dev/github.com/goptics/varmq#Job.Context) ends when someone [cancels the job](#cancelling-a-job) while it runs. The interface has no status and no `Close`.

**The caller gets a handle.** `Add` returns the handle and a `bool`:

```go
job, ok := queue.Add("resize photo")
```

`ok` is `false` when the queue did not take the job. This happens when the queue is full or closed, or when a job with the same ID is still in the queue. In that case `job` is `nil`, so check `ok` before you use it.

With a plain worker the handle is an [`EnqueuedJob`](https://pkg.go.dev/github.com/goptics/varmq#EnqueuedJob). The other two worker types add one method that returns the outcome:

| Worker | `Add` returns | Extra method |
|---|---|---|
| [`NewWorker`](https://pkg.go.dev/github.com/goptics/varmq#NewWorker) | `EnqueuedJob` | none |
| [`NewErrWorker`](https://pkg.go.dev/github.com/goptics/varmq#NewErrWorker) | [`EnqueuedErrJob`](https://pkg.go.dev/github.com/goptics/varmq#EnqueuedErrJob) | `Err() error` |
| [`NewResultWorker`](https://pkg.go.dev/github.com/goptics/varmq#NewResultWorker) | [`EnqueuedResultJob[R]`](https://pkg.go.dev/github.com/goptics/varmq#EnqueuedResultJob) | `Result() (R, error)` |

Every handle has `ID()`, `Status()`, `IsClosed()`, `Wait()`, `WaitContext()`, `Close()` and `Cancel()`. `Err` and `Result` block until the job is closed, then return what the worker function sent. For a job that was closed before it ran, `Err` returns `nil` and `Result` returns the zero value and a `nil` error. See [worker types](/guides/worker-types/) for the three workers side by side.

## Job IDs

A job has no ID unless you give it one. `ID()` returns an empty string by default.

- [`WithJobId`](https://pkg.go.dev/github.com/goptics/varmq#WithJobId) sets the ID of one job: `queue.Add(data, varmq.WithJobId("job-1"))`. An empty string is ignored.
- [`WithJobIdGenerator`](https://pkg.go.dev/github.com/goptics/varmq#WithJobIdGenerator) sets a function that makes IDs. `Add` calls it, on the caller's goroutine, for every job; its value is used when the job has no ID of its own.

An in-memory queue refuses a second `Add` with an ID that a job still in the queue holds. [Job IDs](/guides/job-ids/) covers when an ID is free again, generated IDs and the `g:` prefix of [`AddAll`](https://pkg.go.dev/github.com/goptics/varmq#Queue.AddAll) items.

## Job status

[`Status()`](https://pkg.go.dev/github.com/goptics/varmq#StatusProvider.Status) on a handle returns one of five strings:

| Status | Meaning |
|---|---|
| `Created` | The job exists but `Add` has not stored it yet. A handle you get back from `Add` is past this. |
| `Queued` | The job is waiting. It may be in the queue, in a batch a worker took but has not started, or parked by a [pause or stop](/concepts/lifecycle/). |
| `Processing` | The worker function is running it. |
| `Finished` | The worker function returned. |
| `Closed` | The job is complete: it ran, or it was closed before it could. |

`Finished` is short-lived. As soon as your function returns, the worker closes the job to release anyone waiting on it. By the time [`Wait`](https://pkg.go.dev/github.com/goptics/varmq#Awaitable.Wait) returns, the status is `Closed`, and [`IsClosed()`](https://pkg.go.dev/github.com/goptics/varmq#StatusProvider.IsClosed) is `true`. So `Closed` does not tell you whether the job ran. Record that in your own worker function if it matters.

## Closing a queued job

[`Close()`](https://pkg.go.dev/github.com/goptics/varmq#EnqueuedJob.Close) cancels a job that has not started. It only marks the job closed; it does not take it out of the queue. When the worker reaches a closed job it skips it, and your function never sees it. Closing also releases `Wait` immediately.

It succeeds while the job waits. It fails in two cases:

- A running job returns [`ErrJobProcessing`](https://pkg.go.dev/github.com/goptics/varmq#ErrJobProcessing). To stop a running job, [cancel it](#cancelling-a-job).
- A closed job returns [`ErrJobAlreadyClosed`](https://pkg.go.dev/github.com/goptics/varmq#ErrJobAlreadyClosed). That includes a job that already ran, since the worker closes those too.

On shared storage, `Close` only stops this handle from waiting. It returns `nil`, `Err` then returns `ErrDetached`, and the job still runs.

Until the worker reaches it, a job closed while it waited still counts in the queue's `Len()` and in the worker's `NumPending()`. Because it never ran, it never counts as completed.

## Cancelling a job

[`Cancel()`](https://pkg.go.dev/github.com/goptics/varmq#EnqueuedJob.Cancel) stops a job, whether it waits or runs.

- **A job that has not started** is closed and never runs. On an error or result worker, `Err` or `Result` returns [`ErrJobCancelled`](https://pkg.go.dev/github.com/goptics/varmq#ErrJobCancelled).
- **A running job** has its `Context()` cancelled. VarMQ cannot stop your function, so the function must watch `j.Context()` and return.
- **A running job that then returns an error, or panics,** ends cancelled, and `Err` returns `ErrJobCancelled`. If it returns without an error, it ends as usual.
- **A job that has ended** returns [`ErrJobAlreadyClosed`](https://pkg.go.dev/github.com/goptics/varmq#ErrJobAlreadyClosed).

```go
worker := varmq.NewErrWorker(func(j varmq.Job[string]) error {
	select {
	case <-time.After(time.Minute):
		return nil
	case <-j.Context().Done():
		return j.Context().Err()
	}
})
queue := worker.BindQueue()

job, _ := queue.Add("report")
job.Cancel()
fmt.Println(job.Err()) // varmq: job cancelled
```

On shared storage, `Cancel` reaches the job in whichever process holds it. A waiting [workflow](/guides/workflows/#cancelling-a-workflow) task is the exception: cancel its workflow. The storage must support it. Without that support, `Cancel` returns [`ErrCancelUnsupported`](https://pkg.go.dev/github.com/goptics/varmq#ErrCancelUnsupported). The [REST API](/operations/rest-api/#queues-and-jobs) can cancel a job by its ID too.

## Jobs in other processes

On shared storage such as Redis or SQLite, another process can run the job. The handle that `Add` returns still learns how the job ended, if the storage reports outcomes. A producer that runs no worker gets the same handles from [`NewQueue`](https://pkg.go.dev/github.com/goptics/varmq#NewQueue), [`NewErrQueue`](https://pkg.go.dev/github.com/goptics/varmq#NewErrQueue) or [`NewResultQueue`](https://pkg.go.dev/github.com/goptics/varmq#NewResultQueue).

- **`Err`** returns `nil` for a completed job. For a failed job it returns a [`*RemoteError`](https://pkg.go.dev/github.com/goptics/varmq#RemoteError). It holds only the error text, so `errors.Is` does not match your own error values.
- **`Result`** decodes the result from JSON. It returns [`ErrNoResult`](https://pkg.go.dev/github.com/goptics/varmq#ErrNoResult) when the storage kept no result, for example a result over 64 KiB.
- **[`ErrDetached`](https://pkg.go.dev/github.com/goptics/varmq#ErrDetached)** means this handle cannot learn the outcome. The storage does not report outcomes, you called `Close` on the handle, or you called `Purge` or `Close` on the queue handle that added the job. The job itself still runs.

A job on storage that reports outcomes or cancels jobs always has an ID: when you give none, VarMQ makes a random one. To wait on a job from a process that did not add it, use [`OpenJob`](https://pkg.go.dev/github.com/goptics/varmq#OpenJob), [`OpenErrJob`](https://pkg.go.dev/github.com/goptics/varmq#OpenErrJob) or [`OpenResultJob`](https://pkg.go.dev/github.com/goptics/varmq#OpenResultJob) with that ID. The storage finds a job that already ended while it keeps the job's record. [Persistence](/persistence/overview/) says which storage supports this.

## Waiting on a job

[`Wait()`](https://pkg.go.dev/github.com/goptics/varmq#Awaitable.Wait) blocks until the job is closed, whether it ran or you closed it. If that has already happened, it returns immediately. [`WaitContext`](https://pkg.go.dev/github.com/goptics/varmq#Awaitable.WaitContext) does the same, but gives up when its context ends. To wait for everything a worker has queued instead of one job, see [waiting](/guides/waiting/).
