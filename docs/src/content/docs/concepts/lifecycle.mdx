A worker is always in one of seven states. [`Status()`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Status) returns the current one as a string, and five `Is*` methods answer yes or no for some of them.

## The seven states

| State | What it means | `Is*` check |
|---|---|---|
| `Initiated` | Created with `WithAutoRun(false)` and not started yet. | none |
| `Idle` | Started, with no job running. | [`IsIdle`](https://pkg.go.dev/github.com/goptics/varmq#Worker.IsIdle), [`IsActive`](https://pkg.go.dev/github.com/goptics/varmq#Worker.IsActive) |
| `Running` | At least one job is running. | [`IsRunning`](https://pkg.go.dev/github.com/goptics/varmq#Worker.IsRunning), `IsActive` |
| `Pausing` | `Pause` was called while jobs were running. They finish, and the worker takes no new ones. | none |
| `Paused` | No job is running and none will start until `Resume`. | [`IsPaused`](https://pkg.go.dev/github.com/goptics/varmq#Worker.IsPaused) |
| `Stopping` | `Stop` was called. Running jobs finish, then the worker's goroutines are removed. | none |
| `Stopped` | The event loop has ended and the goroutines are gone. Jobs still in the queue stay there. | [`IsStopped`](https://pkg.go.dev/github.com/goptics/varmq#Worker.IsStopped) |

`Idle` and `Running` swap on their own as jobs start and finish, so `Running` is a moment, not a mode you set. `IsActive` is true for either of them, which makes it the check for "started and not paused or stopped".

A status is a snapshot. Between reading it and acting on it the worker may have moved on. To know where a worker has landed after `Pause` or `Stop`, use the [waiting helpers](#waiting-for-a-state) below.

## Moving between states

| Call | From | Result | Errors from other states |
|---|---|---|---|
| [`Start`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Start) | `Initiated`, `Stopped` | `Idle` | [`ErrRunningWorker`](https://pkg.go.dev/github.com/goptics/varmq#ErrRunningWorker) from `Idle` or `Running`; [`ErrWorkerPausing`](https://pkg.go.dev/github.com/goptics/varmq#ErrWorkerPausing), [`ErrWorkerPaused`](https://pkg.go.dev/github.com/goptics/varmq#ErrWorkerPaused) or [`ErrWorkerStopping`](https://pkg.go.dev/github.com/goptics/varmq#ErrWorkerStopping) |
| [`Pause`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Pause) | `Idle` becomes `Paused`; `Running` becomes `Pausing`, then `Paused` | already `Pausing` or `Paused`: no error | [`ErrNotRunningWorker`](https://pkg.go.dev/github.com/goptics/varmq#ErrNotRunningWorker) from `Initiated`; `ErrWorkerStopping`; [`ErrWorkerStopped`](https://pkg.go.dev/github.com/goptics/varmq#ErrWorkerStopped) |
| [`Resume`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Resume) | `Paused` becomes `Idle`, and the worker pulls jobs again | already `Idle` or `Running`: no error | `ErrNotRunningWorker` from `Initiated`; `ErrWorkerPausing`; `ErrWorkerStopping`; `ErrWorkerStopped` |
| [`Stop`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Stop) | `Idle`, `Running`, `Pausing` or `Paused` become `Stopping`, then `Stopped` | already `Stopping` or `Stopped`: no error | `ErrNotRunningWorker` from `Initiated` |
| [`Restart`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Restart) | any state but `Initiated` | stops, waits for `Stopped`, starts again: `Idle` | `ErrNotRunningWorker` from `Initiated` |

The errors are values in the package, listed under [Variables](https://pkg.go.dev/github.com/goptics/varmq#pkg-variables). Two details:

- `Pause`, `Resume` and `Stop` return at once. `Restart` does not: it waits for running jobs to finish before it starts the worker again. If another goroutine restarts the worker first, it returns `ErrRunningWorker`.
- A stopped worker cannot be resumed. `Resume` returns `ErrWorkerStopped`. Use `Restart`, or `Start`, which also accepts a stopped worker.

### What happens to jobs

Pause and stop never interrupt a running job. Each running job finishes first.

Jobs that have not started stay queued and are not lost. A worker may have taken several jobs from the queue at once (see [how it works](/concepts/how-it-works/)). On pause or stop it finishes the job it is running and parks the rest of the batch. Parked jobs are still `Queued`, and the worker's [`NumPending`](https://pkg.go.dev/github.com/goptics/varmq#Worker.NumPending) counts them, but the queue's `Len()` does not. They run first, in their original order, after `Resume` or `Restart`. [`Purge`](https://pkg.go.dev/github.com/goptics/varmq#IExternalBaseQueue.Purge) closes them.

A stop also cancels the worker's [`Context()`](https://pkg.go.dev/github.com/goptics/varmq#Worker.Context). A restart gives the worker a fresh one.

### Waiting for a state

`Pause`, `Resume` and `Stop` only start the change. These block until it is done:

- [`PauseAndWait`](https://pkg.go.dev/github.com/goptics/varmq#Worker.PauseAndWait) is `Pause` followed by `WaitUntilPaused`.
- [`StopAndWait`](https://pkg.go.dev/github.com/goptics/varmq#Worker.StopAndWait) is `Stop` followed by `WaitUntilStopped`.
- [`WaitUntilPaused`](https://pkg.go.dev/github.com/goptics/varmq#Worker.WaitUntilPaused) and [`WaitUntilStopped`](https://pkg.go.dev/github.com/goptics/varmq#Worker.WaitUntilStopped) wait for one state, and never return if the worker does not reach it.
- [`WaitUntilIdle`](https://pkg.go.dev/github.com/goptics/varmq#Worker.WaitUntilIdle) waits for `Idle` with no pending jobs, so on a paused or stopped worker it keeps waiting until `Resume`, `Restart` or `Start` brings it back to `Idle` and it drains.

[`WaitAndPause`](https://pkg.go.dev/github.com/goptics/varmq#Worker.WaitAndPause) and [`WaitAndStop`](https://pkg.go.dev/github.com/goptics/varmq#Worker.WaitAndStop) go the other way: they call `Wait` first, then pause or stop. [Waiting](/guides/waiting/) compares all of them.

## Try it

This program creates a worker with `WithAutoRun(false)`, adds three jobs, and walks it through pause, resume, stop and restart. The first job is held inside the worker function until the program releases it, so the worker is busy at the moment `Pause` is called.

<GoPlay example="lifecycle" />

The output, line by line:

1. `created: Initiated`. The worker exists but has not started.
2. `Start: Idle`. It is started and has nothing to do.
3. `Pause: Pausing`. Job 1 is running, so the pause cannot complete yet. This line prints before job 1 is allowed to finish.
4. `job 1 done`. The program released job 1.
5. `paused: Paused - IsPaused: true - IsActive: false`. `PauseAndWait` returned, so the state is `Paused` and `IsActive` is false.
6. `jobs still waiting: 2`. Jobs 2 and 3 did not run during the pause.
7. `job 2 done` and `job 3 done`. After `Resume` they run, in order. `Resume, then drained: Idle - IsIdle: true` follows once the queue is empty.
8. `StopAndWait: Stopped - IsStopped: true`.
9. `Resume: worker is stopped`. `Resume` refuses a stopped worker.
10. `job 4 done`. Job 4 was added while the worker was stopped. It waited in the queue, and `Restart` brought the worker back to run it. The last line is `Restart, then drained: Idle`.

## Settings

### `WithAutoRun`

[`WithAutoRun`](https://pkg.go.dev/github.com/goptics/varmq#WithAutoRun) decides whether the worker starts when you create it. The default is `true`: `NewWorker` returns a worker that is already `Idle`, and `Start` on it returns `ErrRunningWorker`.

Pass `WithAutoRun(false)` to get an `Initiated` worker instead. You can bind queues and add jobs to it right away. The jobs wait until you call `Start`. Use it when you want to finish setting things up before any job runs.

### `WithStoppedRetention`

This setting matters only for a worker with a name ([`WithName`](https://pkg.go.dev/github.com/goptics/varmq#WithName) or a string argument to `NewWorker`). `Start` adds a named worker to [`WorkerRegistry`](https://pkg.go.dev/github.com/goptics/varmq#WorkerRegistry), the map that the REST [`Handler`](https://pkg.go.dev/github.com/goptics/varmq#Handler) reads. A worker without a name is never registered.

When a registered worker reaches `Stopped`, it stays in the registry for a while, so it still shows up as `Stopped`. [`WithStoppedRetention`](https://pkg.go.dev/github.com/goptics/varmq#WithStoppedRetention) sets how long. When the time is up and the worker is still stopped, it is removed from the registry.

- The default is one minute. [`DefaultStoppedRetention`](https://pkg.go.dev/github.com/goptics/varmq#DefaultStoppedRetention) changes the default for workers created after the call.
- `0` turns the cleanup off: a stopped worker stays in the registry for good.
- Starting the worker again cancels the timer, and re-registers the worker if it had already been removed.

```go
worker := varmq.NewWorker(process, 2,
	varmq.WithName("emails"),
	varmq.WithStoppedRetention(10*time.Minute),
)
```
