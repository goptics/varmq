VarMQ needs Go 1.27 or newer. Add it to your module with `go get`, then import it. Pick the variant you need:

<InstallTabs />

The in-memory worker pool, queues and topics are all in this one package. Shared storage also needs a storage adapter, which is its own module: [redisq](https://github.com/goptics/redisq) for Redis or [sqliteq](https://github.com/goptics/sqliteq) for SQLite.

## Versions

`go get` without a version takes the latest release of each module. Use the latest releases of VarMQ and its adapters together.

| Module | Go version | Other needs |
|---|---|---|
| `github.com/goptics/varmq` | 1.27 or newer | None. |
| `github.com/goptics/varmq/contract` | 1.24 or newer | None. VarMQ and the adapters import it. |
| `github.com/goptics/redisq` | 1.26 or newer | Redis 6.0 or newer, with Lua scripts allowed. |
| `github.com/goptics/sqliteq` | 1.27 or newer | cgo (`CGO_ENABLED=1`) and a C compiler, because it uses `mattn/go-sqlite3`. |

Your module needs the highest Go version of the modules it uses. With VarMQ, that is Go 1.27.

### What the adapters support

redisq and sqliteq support these features:

- Binding with `WithQueue`, and producers with `NewQueue`
- [`Reject`](/persistence/overview/#acknowledgement) of a failed job
- [Job outcome](/concepts/jobs/#jobs-in-other-processes) and [cancel](/concepts/jobs/#cancelling-a-job)
- [Queue pause](/guides/queues/#pausing-a-queue)
- Job records for the [REST API](/operations/rest-api/#queues-and-jobs)
- [Workflows](/guides/workflows/)

Neither adapter reads one job by its ID. For their queues, that REST route answers 501.

:::caution
Older adapter releases do not work with this VarMQ: redisq v1.5.1 and older, and sqliteq v0.3.0 and older. They do not have `Reject`. Your module compiles, but `WithQueue` does not bind them as shared storage: jobs are not stored as JSON and are not acknowledged.
:::
